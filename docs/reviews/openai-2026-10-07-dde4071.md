Blocker, lib/ldap_sync/dry_run/user.rb:40
The stubbed method update_attributes is defined without any dry-run guard and with an empty body. This permanently replaces User#update_attributes for all code paths (not only during DRY_RUN), causing any call to user.update_attributes(...) to silently no-op and return nil.
Failure scenario: In a normal (non-rake) request, any plugin or legacy code that still calls user.update_attributes(...) (common in older Redmine plugins) will appear to succeed but will not persist any changes, leading to hard-to-diagnose data loss. This also masks NoMethodError that Rails 8 would otherwise raise, making the failure silent.
Fix: Add the dry-run guard and delegate otherwise. For example:
def update_attributes(attrs = {})
  return super unless LdapSync::DryRun.enabled?
  assign_attributes(attrs)
  true
end
Alternatively, remove this stub entirely if nothing in the sync path calls update_attributes on User.

Resolution: fixed in 4154843: the stub passes through unless the dry run is enabled; test "DRY_RUN stubs should only act while the dry run is enabled" (fails before). It only mattered in a process where the stubs were prepended (rake with DRY_RUN, tests): the web process never calls LdapSync::DryRun.enable!.

Minor, lib/ldap_sync/dry_run/group.rb:26
find_or_create_by_lastname is implemented as an instance method but calls find_by_lastname and Group.new as if it were a class method. If ever invoked as written (on a Group instance), it will raise NoMethodError for find_by_lastname.
Failure scenario: If any code path accidentally calls some_group.find_or_create_by_lastname(...) (or if method lookup gets here due to refactoring), it will crash the dry-run with NoMethodError. Even if not called today, this is a latent bug and contradicts intent (the sync logic uses class-level “find or create”).
Fix: Move it under a ClassMethods module and prepend it to Group.singleton_class in LdapSync::DryRun.enable!, mirroring the User create stub:
module ClassMethods
  def find_or_create_by_lastname(lastname, attributes = {})
    return super unless LdapSync::DryRun.enabled?
    group = find_by_lastname(lastname)
    return group if group.present?
    group = ::Group.new(attributes.merge(:lastname => lastname))
    puts "   !! New group '#{lastname}'" if group.valid?
    group
  end
end
and in enable!: ::Group.singleton_class.prepend(Group::ClassMethods) unless ::Group.singleton_class < Group::ClassMethods

Resolution: not changed. find_or_create_by_lastname is part of the old stubs restored by Jan's decision n2-2 and is on no call path: the sync creates groups through find_or_create_group (Group.new + save, covered by fix 5, 2bf8745); nothing calls find_or_create_by_lastname on a Group instance or class. Moving or rewriting dead code adds risk without effect.
